# CC指示書: /riders-map オンボーディング（使い方）実装

**ブランチ: `feat/riders-map-onboarding`**（main から作成・マージは `--no-ff`・`git add` は個別ファイル指定、`-A` 禁止）

**コピー原稿は別紙 `riders-map-onboarding-copy-20260709.md` を参照。画面に載せる文言はそちらの `【コピー】` ブロックをそのまま使う。**

## 背景と目的

宣伝の着地点になる /riders-map に「これは何で・どう使うか」が無く、広告からの初見流入がレイヤートグルとピンだけ見せられて離脱する。個別ツーリング記事（/touring 配下）が SEO ランディングを担う一方で、マップ本体の「使い方」が空いている。この穴を塞ぐ。

## スコープ

**やること**
- (a) 初回オンボーディングカード（マップ上部・初回のみ・dismiss 記憶）
- (b) 常設の使い方セクション（ページ下部 or トグル・SEO 兼用・常時 DOM）

**やらないこと**
- 新規ルート・migration・config 追加（Blade/JS/CSS の範囲で収める）
- 既存マップ機能（5レイヤー表示・ルート作成・AIルート提案・記事カード横スクロール）の挙動変更
- 「ガイドを書く」UGC 投稿導線の強化（(b) 末尾に存在明示のみ・CTA にしない）

## ステップ0: UIラベルの突き合わせ（実装前・報告に含める）

原稿はスクショ基準で以下のラベルを使用している。**実装時点の実 UI と突き合わせ、食い違いがあれば実 UI を優先して差し替え、報告に差分を明記すること。**

- レイヤー: ショップ / 駐車場 / GS / コンビニ / 道の駅 / 記事 / お気に入り
- アクション: ルート作成 / AIルート提案 / ガイドを書く / ピン留め
- 検索窓プレースホルダ: 「地名・住所で検索（例：渋谷、橋本駅）」
- 記事パネル CTA: 「ガイドを読む →」

あわせて、次を確認・報告:
1. 「AIルート提案」アクションを発火する既存関数/イベント名（(a) の主 CTA から同じものを呼ぶ）
2. 既存の dismiss 系スクリプト（`engagement-banner.js` / `registration-promo.js` 等）の `_isDismissedWithin(key)` ヘルパの所在（流用元）
3. マップページの Blade / JS ファイルの所在と、JS のキャッシュバスター方式（filemtime ベースの既存運用に乗せる）

## 実装

### (a) 初回オンボーディングカード

- 文言は原稿 (a) の `【コピー】` をそのまま使用。3チップ（駐車場/給油/記事）＋2 CTA。
- **CTA の主従**: 「AIにルートを提案してもらう →」を**主ボタン**（既存アクセントカラー）、「ツーリング記事から探す」を**従（テキストリンク調）**。
- 「AIにルートを提案してもらう →」は**既存の「AIルート提案」アクションと同じ関数を発火**（新規実装しない・ステップ0-1 で特定したもの）。
- 「ツーリング記事から探す」は /touring へ遷移（実装しやすければ「記事」レイヤー ON でも可・回遊先が B 記事群に届けばよい）。
- **初回のみ表示・× で dismiss**。dismiss 状態は localStorage に記憶（既存 `_isDismissedWithin` パターン流用・キー `riders_map_onboarding_dismissed_at`）。**再表示間隔は無期限（一度理解したら再表示不要）**。
- 配置: 地図上部（検索窓の近く）。z-index は地図操作・ボトムナビを妨げない層（ボトムナビより下・地図コントロールと非干渉）。
- モバイル: コンパクト化。3チップは折り返し可、CTA はタップしやすい余白。地図の初期表示を大きく覆わないこと。

### (b) 常設の使い方セクション

- 文言は原稿 (b) の `【コピー】` をそのまま使用。
- 配置: /riders-map の下部、または上部の「？使い方」トグルで開閉。
- **中身は常時 DOM**（折りたたみ時も `display:none` で消さない・高さ制御等で。SEO で本文を拾わせるため）。
- 見出しは h2（使い方）＋ h3（各節・表示切替/行き先を探す/ルートを引く/記事から計画する）。
- 末尾の「ピン留め」「ガイドを書く」は存在明示のみ（CTA 化しない）。

## テスト

- 初回表示 → × dismiss → 再訪で非表示（localStorage 記憶）
- (b) の本文が DOM に存在すること（折りたたみ状態でも）
- 「AIにルートを提案してもらう →」クリックで既存 AI ルート提案が起動（新規関数を作っていないこと）
- 「ツーリング記事から探す」の遷移先が正しい
- 既存マップ挙動の回帰（5レイヤー表示・ルート作成・AI提案・記事カード横スクロールが不変）

Feature/JS テストの粒度は既存のマップ関連テストに合わせる。既存テスト全緑を維持・Pint クリーン。

## 内田さん用デプロイメモ（参考・CC は触らない）

route/config 非変更・Blade/JS/CSS のみの想定:

1. `git pull --ff-only origin main`
2. `php artisan view:clear && php artisan view:cache`（Blade 変更）
3. JS 変更ぶんのキャッシュバスター反映（既存 filemtime ベースの運用どおり）
4. `docker compose restart app`（OPcache 確定リセット）
5. スモークテスト（deploy-blog.sh。/riders-map が 200 であること）

route:clear / config:cache は今回不要（ルート・config 非変更）。cache:clear / optimize:clear は禁止。

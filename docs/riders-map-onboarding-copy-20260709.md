# /riders-map オンボーディング原稿（A：使い方・冷たい流入の離脱防止）

宣伝の着地点になる /riders-map に「これは何で・どう使うか」を足す。個別ツーリング記事（/touring 配下）が B（SEOランディング）を担っている一方、マップ本体には使い方が無く、広告からの初見流入がトグルとピンだけ見せられて離脱する穴を塞ぐ。

コピーは **(a) 初回オンボーディング（主役）** と **(b) 常設の使い方（補助・SEO兼用）** の2本。UI ラベルはスクショ実機に合わせてある。「ガイドを書く」は推さず、(b) 末尾に存在だけ添える。

以下、`【コピー】` はそのまま画面に載せるテキスト、`【メモ】` は CC 向けの実装指示。

---

## (a) 初回オンボーディング ── マップ上部カード

初見が3秒で「何ができるか」を掴む。全レイヤーは説明せず、駐車場・給油・記事の3点＋1アクションに絞る。

【コピー】

> **このマップでできること**
>
> 行きたいエリアを開くと、バイク駐車場・給油ポイント・道の駅・ツーリング記事が地図に重なります。気になる場所をタップして、そのまま走るルートも引けます。
>
> ・🅿️ 駐車場を探す ・⛽ 給油ポイント ・🔥 ツーリング記事
>
> [ AIにルートを提案してもらう → ]　[ ツーリング記事から探す ]

【メモ】
- 配置: 地図の上部にカード（検索窓の近く）。**初回のみ表示・× で dismiss**。dismiss 状態は localStorage に記憶（既存 `engagement-banner.js` / `registration-promo.js` の `_isDismissedWithin(key)` パターンを流用。キー例 `riders_map_onboarding_dismissed_at`、再表示までは長め or 無期限でよい）。
- z-index: 地図操作・ボトムナビを妨げない層に（ボトムナビより下、地図コントロールと非干渉）。
- モバイル: さらにコンパクトに。3チップは折り返し可、ボタンはタップしやすい余白。
- 「AIにルートを提案してもらう →」ボタンは、**既存の「AIルート提案」アクションと同じ関数を発火**（新規実装しない）。
- 「ツーリング記事から探す」は /touring（記事一覧）へ遷移、または「記事」レイヤーを ON にする、のどちらか実装しやすい方。回遊先が B 記事群に届けばよい。

## (b) 常設の使い方 ── ページ下部 or「？使い方」トグル

じっくり読む人向け＋「ライダーズマップ 使い方」系クエリの受け皿。h2/h3 構造で常時 DOM に置く（折りたたみでも中身は hidden でなく展開可能に＝SEO のため）。

【コピー】

> ## ライダーズマップの使い方
>
> MotoHub のライダーズマップは、ツーリングの計画から当日のナビまでを1枚の地図で完結できる機能です。どこを走るか決める、停める場所を確認する、給油や休憩のポイントを押さえる ── バイクならではの「困りごと」を先回りして解決します。
>
> ### 表示する情報を切り替える
> 地図の左上のボタンで、表示する情報を切り替えられます。必要なものだけ重ねれば、地図をすっきり保てます。
> - **駐車場** ── バイクを停められる駐車場。都市部では事前確認が特に役立ちます
> - **GS** ── ガソリンスタンド。山間部や半島の先端など、給油できる場所が限られるエリアで重宝します
> - **道の駅** ── 休憩・食事・地元名物のスポット。ツーリングの立ち寄り先の定番です
> - **ショップ** ── バイクの販売店・整備店
> - **コンビニ** ── トイレ・軽食・現金の補給に
> - **記事** ── MotoHub のツーリングガイド。走って気持ちいいルートを、季節や難易度つきで紹介します
> - **お気に入り** ── お気に入り登録した車両を地図に表示します（ログイン時）
>
> ### 行き先を探す
> 上部の検索窓に地名や駅名を入れると、その周辺に地図が移動します（例：渋谷、橋本駅）。行きたいエリアが決まっているなら、まずここから。
>
> ### ルートを引く
> - **ルート作成** ── 立ち寄りたい地点を順につないで、自分だけのルートを作れます
> - **AIルート提案** ── 「日帰りで峠を走りたい」「海沿いをのんびり」といった希望を伝えると、AI がルートを提案します。できたルートは Google マップのナビにも渡せるので、当日はそのまま走り出せます
>
> ### ツーリング記事から計画する
> どこを走るか迷ったら、「記事」レイヤーをオンにしてみてください。地図上のピンや下部のカードから、エリアごとのツーリングガイドを開けます。各ガイドには見どころ・所要時間・おすすめの季節・注意点がまとまっており、記事内の地図からはそのままライダーズマップに戻って続きを計画できます。
>
> ---
> ※ このほか、走ったルートや行きたい場所を残す「ピン留め」、あなたのおすすめルートを投稿する「ガイドを書く」機能もあります。

【メモ】
- 配置: /riders-map の下部、または上部の「？使い方」トグルで開閉。**中身は常時 DOM**（折りたたみ時も `display:none` で消さず、高さ制御等で。SEO で本文を拾わせるため）。
- 見出しは h2（使い方）＋ h3（各節）。「ライダーズマップ 使い方」「バイク ツーリング 地図」等の検索を意識。
- 末尾の「ピン留め」「ガイドを書く」は**存在の明示のみ**（CTA にしない）。UGC 投稿の本格導線は賑わいが育ってから別途。

## 実装全体メモ（CC 向け・指示書化はコピー確定後）

- **UI ラベルは実装時点の画面と完全一致させること。** 本原稿はスクショ基準（レイヤー: ショップ/駐車場/GS/コンビニ/道の駅/記事/お気に入り、アクション: ルート作成/AIルート提案/ガイドを書く/ピン留め、検索窓: 「地名・住所で検索（例：渋谷、橋本駅）」、記事パネル: 「ガイドを読む →」）。**もし実 UI と食い違う箇所があれば実 UI を優先し、報告に差分を明記。**
- 新規ルート・migration は不要の想定（Blade/JS/CSS の範囲）。config も追加しない見込み。
- localStorage は本番サイト側で問題なく使用可（既存の dismiss 系スクリプトと同じ）。
- テスト観点: 初回表示 → dismiss → 再訪で非表示、(b) の本文が DOM に存在（折りたたみでも）、「AIにルートを提案」クリックで既存 AI 提案が起動、記事 CTA の遷移先。既存のマップ挙動（5レイヤー表示・ルート作成・AI提案・記事カード横スクロール）は不変。
- デプロイは軽い側の想定: `git pull` → `view:clear && view:cache`（Blade 変更）→ 必要に応じ JS のキャッシュバスター（既存 filemtime ベース）→ `restart app` → スモーク。route/config 非変更なら route:clear/config:cache は不要。

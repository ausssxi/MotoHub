## 6. 本番スケジューラ（cron）の確認方法

- アプリ側には Laravel スケジュールが**多数定義済み**（`routes/console.php`）。例: `backup:run` dailyAt('03:10')、`blog:generate-sitemap` dailyAt('03:00')、`youtube:refresh` 等。
- これらが実際に動くには、本番の system cron が毎分 `php artisan schedule:run` を叩いている必要がある。**確認手順**:
  1. `crontab -l | grep schedule:run`（または `/etc/cron.d/` 配下）に `* * * * * ... artisan schedule:run` があるか。
  2. `docker exec -e HOME=/tmp motohub-app php artisan schedule:list` で登録タスク一覧を確認。
  3. 実際に発火している証拠として `storage/logs/backup.log` 等の**最終更新が日次で更新されているか**を見る（appendOutputTo 済みのため）。
- 月1回の料金更新は第2段階2-3で `Schedule::command('rental-bike:fetch-price ...')->monthlyOn(1, '04:40')` のように追加する想定（本調査では追加しない）。

## 追記: 819 の P-class → cc 調査（2026-09-28）

### 1〜2. 車両一覧で P-class と排気量が分かるか / 各 P-class の排気量範囲
- 819 の車両一覧は **`/search/`**。ただし**バイクのカード（車種・クラス・排気量）は JS で後読み**され、静的HTMLにも JS無しレンダリング（WebFetch）にも**個々の車両の P-class・cc は出てこない**。
- `/search/` の絞り込みUIにあるのは:
  - **排気量フィルタ＝「50cc以下 / 125cc以下 / 400cc以下 / 400cc超」の4区分のみ**（＝125〜250 と 250〜400 を「400cc以下」に束ねており、MotoHub の 250/400 を区別しない）。
  - 「クラス」絞り込みの選択肢（P-1〜P-6）と各クラスの cc 範囲も **JS後読みで、静的には定義が出ない**。
- 店舗ページ `/store/{id}` の「ラインナップ」は宣伝文で、車両表ではない（class/cc なし）。
- → **結論: 819 は P-class ↔ cc の対応表を公開していない**。料金は P-1〜P-6（6区分）だが、どの排気量がどの P-class かは公開ページから機械的に取れない。

### 3〜4. MotoHub 5車格への対応案 / 1つの P-class が2車格にまたがる場合
- 公開データから確定できないため、**2-2 の実装前に「実データで1回だけ確定」する**のが安全。確定方法の候補:
  - (a) `/search/` の裏で使われる検索API（JSON）を1回だけ叩き、返る各車両の (P-class, 排気量, 車種) から P-class ごとの cc 範囲を集計する（robots/規約OKの範囲で・2秒待ち・1回）。
  - (b) 819 に P-class の定義（対象排気量）を問い合わせる。
- 対応は **config に手で持つ**（下記5）。1つの P-class が MotoHub の2車格にまたがる場合の扱い案:
  - **原則、その P-class を「代表車格1つ」に寄せる**（またがり時は**下位の車格**に寄せ、参考価格を過大に見せない）。
  - 例（★実データ確認前の暫定・要検証）: P-1→原付/125、P-2→125/250、P-3→250/400、P-4→400/大型、P-5・P-6→大型（輸入・大型）。まずは (a) の実データで補正する前提。
  - 表示側では「819は独自クラスのため、MotoHub車格は目安」と注記できるようにする。

### 5. config か毎月自動判定か
- **config に手で持つ（推奨）**。理由:
  - P-class は6区分・変更頻度が低い（料金改定はあってもクラス区分の入れ替えは稀）。
  - 毎月の自動判定は「全車両を毎回スクレイプして cc 範囲を再推定」する重い処理になり、AJ を外した意義（軽く・壊れにくく）に反する。
  - config 例（`config/rental_bike.php`）: `'class_map' => ['rental819' => ['P-1' => '125cc', 'P-2' => '250cc', ...]]` のように **P-class → MotoHub車格** を持つ。値は 2-2 で (a) により1回確定し、819の料金改定時だけ見直す。
- ヤマハ・二輪処は排気量ベースなので config 不要（パース時に cc→車格を機械判定できる。二輪処は1:1、ヤマハは境界判定）。819 だけ class_map を持つ。

### この調査での結論（819）
- **819 の料金は取り込める（静的HTML表・OK）が、P-class→車格の対応は公開されていない**。2-2 の前に検索API等で**1回だけ実データ確定→config の class_map に固定**する方針。またがりは下位車格へ寄せる。月次自動判定はしない。
